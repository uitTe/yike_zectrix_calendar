# 01 · 首次刷机操作手册

> 适用：Zectrix Note 4（黑白墨水屏成品设备，ESP32-S3 N16R8）
> 本手册是**本项目实际要执行的顺序**，不是通用教程。每一步都可回退。
> 上级设备的规格 / 刷机决策 / 救砖资料见 `D:\zectrix\docs\`（尤其 `10-固件回滚与救砖指南.md`、`11-刷机决策指南.md`）。

---

## 0 · 全局红线（每次动手前扫一遍）

| # | 红线 |
|---|---|
| 1 | **刷任何固件之前，先完成 16 MiB 原厂 Flash 全量备份**，并通过自检。这是恢复出厂原样的唯一退路。 |
| 2 | **绝不开启 Secure Boot / Flash Encryption** —— 会烧 eFuse，是**唯一真正不可逆**的操作，永久无法退回原厂。 |
| 3 | 必须用**支持数据传输**的 USB 线，直连不过 HUB。只充电的线能供电但不出串口。 |
| 4 | 写入期间绝不拔线 / 断电 / 让电脑休眠。 |
| 5 | 不同项目的分区布局可能不同；本项目基座（官方 Demo）是 **`factory` 单分区、无 otadata**，刷入会替换原厂分区表。 |

**救回路径**：极趣云平台 →「本地升级」→ 选官方版本 → 写 `0x0` 全量镜像（已实机确认，可勾选「保留设备数据」）。即使分区表被改也能重写救回。

## 1 · 按键与下载模式

屏幕朝向使用者时：

| 位置 | 硬件信号 | 说明 |
|---|---|---|
| 右侧上键 | `GPIO39` | 上键，低电平有效 |
| 右侧下键 | `GPIO18` | 下键 / 电源相关输入，低电平有效 |
| 正面圆形键 | `GPIO0` | **BOOT / 确认（同时是语音键）**，低电平有效，启动配置引脚 |
| 左侧内凹针孔 | `EN / RST` | 短按复位主控，**不清除固件** |

### 进入 ESP32-S3 下载模式

官方文档说明：**多数电脑无需按键即可识别设备**。若串口或刷写工具认不到设备，按下面操作：

1. 保持 USB Type-C 数据线连接；
2. 按住正面圆形 **BOOT / 语音键**（`GPIO0`）不放；
3. 保持按住，同时用细针**短按一次左侧内凹 RESET 针孔**；
4. 松开 BOOT；
5. 回到刷写工具重新连接，选择新出现的 ESP32-S3 串口设备。

> 原理：`GPIO0` 拉低 + 复位 = 进入 ROM 下载模式。ROM bootloader 固化在芯片内部、不在 Flash，所以**固件怎么刷坏都能再进下载模式重刷**，「变砖」基本是伪命题。

**串口波特率**：监视器 `115200`；云平台「本地升级」连接设备用 `921600`。

## 2 · 第一步：备份原厂 Flash（强制）

设备未刷任何第三方固件时，先做**备份 → 立刻原样写回**的**空转测试**，在零风险状态下验证整条恢复链路可用。

```bash
cd D:\zectrix\zectrix_yike

# 2.1 备份（省略 --port 会自动探测串口）
tools\.venv\Scripts\python.exe tools\flash_backup.py backup --port COM5

# 2.2 备份自检（也可单独跑，不需要连设备）
tools\.venv\Scripts\python.exe tools\flash_backup.py verify backup\note4_flash_<时间戳>.bin

# 2.3 空转测试：把备份原样写回
tools\.venv\Scripts\python.exe tools\flash_backup.py restore backup\note4_flash_<时间戳>.bin --port COM5
```

### 自检三要素

| 检查项 | 期望值 |
|---|---|
| 文件大小 | `16777216` 字节（16 MiB） |
| 偏移 `0x0` | `0xE9`（ESP 镜像魔术字节） |
| 偏移 `0x8000` | `AA 50`（分区表魔术字节） |
| 附加：偏移 `0xC` | `0x09`（芯片 ID = ESP32-S3） |

**备份存两份**（本机 `backup/` + 异地移动硬盘或网盘）。`backup/` 已加入 `.gitignore`，绝不入库。

## 3 · 第二步：安装 ESP-IDF

本项目选定版本：**ESP-IDF v5.4.4**（与官方 Demo 声明的 5.4 基线一致；真机验证过的 4BP Gallery 用 5.4.2。**不冒进到 6.0** —— 4BP Gallery 作者明确不建议 IDF 6，上游波形哈希校验有问题）。

安装位置（遵守「软件装 D 盘」）：

| 项 | 路径 |
|---|---|
| IDF 本体 | `D:\development_tools\esp\esp-idf` |
| 工具链 / Python 虚拟环境 | `D:\development_tools\esp\espressif`（`IDF_TOOLS_PATH`） |

```bat
:: 进入 IDF 环境（每个新开命令行窗口都要先执行一次）
D:\development_tools\esp\esp-idf\export.bat

:: 验证
idf.py --version
```

## 4 · 第三步：构建与烧录

```bash
cd D:\zectrix\zectrix_yike\firmware
idf.py set-target esp32s3      # 生成 sdkconfig；换 target 前先删掉旧的 sdkconfig
idf.py build
idf.py -p COM5 flash monitor   # 退出监视器 Ctrl+]
```

### 备用路径：直接烧官方预编译合并镜像

`dist/official/zectrix-note4-epd-demo-v1.0.0.bin`（1,074,896 字节，写地址 `0x0`，
SHA-256 `a3649af0…318072` 已核对与官方公布一致）。不需要 ESP-IDF，只要 esptool：

```bash
tools\.venv\Scripts\python.exe -m esptool --port COM5 --baud 460800 write_flash --flash_size 16MB 0x0 dist\official\zectrix-note4-epd-demo-v1.0.0.bin
```

用途：**先验证烧录链路本身是否通**，把「工具链问题」和「硬件/连线问题」解耦开排查。

---

## 5 · 第四步：验证

烧录成功后设备应依次轮播：1bpp 全刷灯塔 → 1bpp 局刷六步脚印 → 4bpp 十六灰阶山水画。
按键：上/下键移动选项，OK 选择，长按 OK 1.5 秒返回，长按下键 3 秒清屏关机。
15 秒无操作自动进入展示模式。

> ⚠️ **USB 供电时无法真正断电**：长按下键 3 秒会清屏并进深度睡眠，这是预期行为。
> 要验证电池锁存关机，需拔掉 USB。

## 6 · 回滚

| 目标 | 手段 |
|---|---|
| 刷回**某个官方版本** | ⭕ 极趣云平台「本地升级」（写 `0x0` 全量镜像，可勾选「保留设备数据」免重配网） |
| 恢复**出厂原样**（含 Wi-Fi 配置与射频校准数据） | ❌ 只有**自己那份 16 MiB 备份**能还原 |
| 恢复到**官方 Demo v1.0.0** | ⭕ 用本手册 §4 的备用路径写 `dist/official/…v1.0.0.bin` |

**注意**：官方平台给的是**维护中的版本线**（当前 `3.6.x`），未必等于设备出厂那一版。

### ✅ 实测记录（2026-09-22）

**原厂出厂固件已确认 = 小智 `xiaozhi` 3.6.5**（ESP-IDF v5.5.2-dirty，运行于 `ota_0`，SKU `zectrix-s3-epaper-4.2`）。
从备份串口日志读出的关键行：

```

I (110) app_init: App version:      3.6.5
I (123) app_init: ESP-IDF:          v5.5.2-dirty
I (10134) Ota: Running partition: ota_0
I (234) Storage: LittleFS mounted at /assets (partition=assets): total=4096 KB
```

**「恢复出厂原样」路径已实际跑通并通过**：

| 步骤 | 结果 |
|---|---|
| 写回 `backup/note4_flash_20260922-161633.bin` | ✅ `Hash of data verified.` / EXIT=0 / **1 分 22 秒** |
| 设备启动 | ✅ 原厂固件完整恢复，功能正常 |
| NVS 数据 | ✅ WiFi 凭据、待办、时区设置**全部还原**（自动连上原网络并取得 IP） |

> ⚠️ **原厂固件会自动 OTA**：启动后即检查 `ota.zectrix.com`，周期 24 h。
> 当前返回「已是最新」，但**云端一旦发新版，设备会自行升级，出厂状态即被改变**。
> 若要长期保存出厂状态，**还原后不要让它长期联网**。
