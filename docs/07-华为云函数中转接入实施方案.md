# 07 · Zectrix Note 4 日历数据接入华为 AGC 云函数实施方案

- **适用项目**：Zectrix Note 4，ESP32-S3，ESP-IDF v5.4.4
- **依据文档**：[06-第三方接入华为云函数方法.md](06-第三方接入华为云函数方法.md)
- **项目数据契约**：[03-台历页规格与数据契约.md](03-台历页规格与数据契约.md) §2、§6
- **当前状态**：**已实施完成**（2026-10-26）。固件侧 WiFi STA、OAuth、云函数调用、缓存与校时均已实现并真机验证；本文记录接入设计与链路约束，请求与响应的实测细节以 `docs/11-AGC接口调用说明.md` 为准
- **接入目标**：使用 AGC OAuth 与中转云函数取得未来 14 天班次数据，交给现有本地历法、渲染与墨水屏流程

## 1. 方案范围与项目决策

本方案把 06 文档中的 AGC OAuth → 中转云函数 → 目标业务云函数链路用于本项目任务 6。设备通过 HTTPS 请求 AGC，目标业务 API 的凭据由目标云函数管理。

本项目的日历数据契约以 `docs/11` 第 5.4 节的实测响应为准：每个日期包含 `date`、`shiftName`、`amStart`、`amEnd`、`pmStart`、`pmEnd`、`remark`。06 文档的示例只展示了 dateRange 转发，未实现真实班次查询；实际业务查询由目标函数接入真实数据源后完成。

03 文档 §6 记录的是「固件直连第三方」与「经中转」两种形态的取舍。最终形态是设备直连 AGC 网关，鉴权与转发由 AGC 云端承担，项目自身不维护常开服务器 —— 这与 03 文档决策 #14 的「不加自建中转层」一致。本文记录任务 6 的目标链路。

## 2. 请求链路

| 顺序 | 调用方 | 接收方 | 操作 |
|---|---|---|---|
| 1 | Note 4 | AGC OAuth | 使用 client_id 和 client_secret 获取短时 access_token |
| 2 | Note 4 | proxy-function | 通过 Bearer Token 和请求体中的 apiKey 请求未来 14 天数据 |
| 3 | proxy-function | query-schedules-range | 检查调用权限和日期范围，通过 Server SDK 调用目标函数 |
| 4 | query-schedules-range | 实际班次数据源 | 查询日期、班次和两个时段，转换为 Note 4 数据契约 |
| 5 | proxy-function | Note 4 | 返回日历数据，并保留可解析的 HTTPS Date 响应头 |
| 6 | Note 4 | 本机 NVS 与显示流程 | 验证数据、更新缓存与 RTC、渲染当天页面、进入 deep sleep |

AGC 网关和所有函数调用均使用 HTTPS。设备不直接访问目标业务函数。

## 3. AGC 云函数配置

### 3.1 目标业务云函数

06 文档中的示例名称为 query-schedules-range，实际名称与版本以 AGC 控制台部署结果为准。

| 配置项 | 要求 |
|---|---|
| 函数类型 | HTTP |
| authFlag | true |
| authType | cloudgw-client |
| authAlgor | HDA-SYSTEM |
| 允许调用方式 | 由中转函数通过 Server SDK 调用 |
| 日期范围上限 | 14 天，服务端拒绝超范围请求 |

目标函数接收中转函数传入的业务数据，执行真实班次查询，并返回第 3.1 节定义的数据契约。只回显请求参数、不含 `days` 实际班次数据的响应不算业务结果。

目标函数返回字段（实测形态）：

| 字段 | 类型 | 规则 |
|---|---|---|
| `code` | number | `200` 表示查询成功 |
| `message` | string | 结果描述 |
| `data.groupId` | string | 回显分组编号 |
| `data.startDate` / `data.endDate` | string | 回显窗口首尾日期 |
| `data.days` | array | 14 条，覆盖请求窗口；不得重复日期 |
| `data.days[].date` | string | 必填，`YYYY-MM-DD` |
| `data.days[].shiftName` | string | 可省略；**省略即该天没有排班** |
| `data.days[].amStart` / `amEnd` | string | 第一段时段，`HH:MM` |
| `data.days[].pmStart` / `pmEnd` | string | 第二段时段，`HH:MM` |
| `data.days[].remark` | string | 备注，设备不使用 |

第一段与第二段不保证分别发生在上午和下午。夜班数据按照源系统原始时间返回，由固件依照 03 文档的开始时间规则生成时段前缀。休息日的时段字段服务端给 `00:00`，解析阶段丢弃。

如果目标函数还需访问原始第三方接口，应将原始接口地址和业务凭据配置在目标函数的 AGC 环境变量中。原始接口凭据不得下发到设备。

### 3.2 中转云函数

06 文档中的示例名称为 proxy-function。函数负责入口鉴权、参数校验、调用目标函数和返回标准日历响应。

| 配置项 | 要求 |
|---|---|
| 函数类型 | HTTP |
| authFlag | true |
| authType | apigw-client |
| authAlgor | HDA-SYSTEM |
| TARGET_FUNCTION_NAME | 目标函数在 AGC 中的实际名称 |
| TARGET_FUNCTION_VERSION | 已部署版本；稳定后填写固定版本 |
| ALLOWED_CLIENT_IDS | 获准调用的 AGC client_id 清单 |
| CUSTOM_API_KEY | 与设备 NVS 中调用方密钥相同 |

中转函数需要完成以下检查：

1. 由 AGC 网关验证 Bearer Token。
2. 检查请求体中的 apiKey 是否与 CUSTOM_API_KEY 相同。
3. 检查经过验证的调用方身份是否属于 ALLOWED_CLIENT_IDS。
4. 检查 `data.startDate` 的格式与合法性、`data.groupId` 是否属于允许范围，以及查询窗口不超过 14 天。
5. 调用 query-schedules-range，并将标准日历响应返回设备。

### 3.3 client_id 来源核实

06 文档的中转函数示例从 event.headers.client_id 读取调用方标识；客户端示例只显式发送 Authorization 和 Content-Type。部署前必须用真实 AGC 请求确认网关是否会注入 client_id。

若网关没有注入该字段，应改用 AGC 提供的、可验证的调用方身份来源。不得仅凭客户端自行提交的普通请求头或 JSON 字段授予白名单权限。

## 4. HTTP 协议

### 4.1 获取 AGC Token

设备向以下地址发送 HTTPS POST：

| 项目 | 值 |
|---|---|
| Host | connect-drcn.dbankcloud.cn |
| Path | /agc/apigw/oauth2/v1/token |
| Content-Type | application/json |
| grant_type | client_credentials |
| client_id | AGC 控制台分配的调用方标识 |
| client_secret | 对应的调用方凭据 |
| useJwt | 0 |

设备从响应中读取 `access_token` 与 `expires_in`（实测约 48.7 小时）。令牌连同绝对过期时刻缓存到 NVS `cal_agc` 的 `token` 与 `expire`，下次唤醒先判定能否复用：过期时刻减去 3600 秒仍晚于当前时间就直接跳过 OAuth。设备每天只醒一次，每次换令牌等于把一次 TLS 握手变成两次，唤醒时长与耗电都翻倍。云函数返回 401 时清掉缓存令牌、换新令牌并重试一次；配网重写凭证时一并清掉令牌。

### 4.2 请求中转云函数

设备向 AGC 网关提供的中转函数触发地址发送 HTTPS POST。地址格式以控制台实际触发 URL 为准，06 文档给出的路径形式为：

    /functions/{projectId}/proxy-function-$latest

请求头：

| 字段 | 值 |
|---|---|
| clientId | AGC Client ID，与 OAuth 的 `client_id` 相同 |
| Authorization | `Bearer ` 后接 access_token |
| productId | 网关路由头，随接口地址写进代码，不属于密钥 |
| Content-Type | application/json |

请求体字段：

| 字段 | 说明 |
|---|---|
| `apiKey` | 与中转函数环境变量 `CUSTOM_API_KEY` 一致的调用方密钥，放在请求体里 |
| `data.groupId` | 班次分组编号 |
| `data.startDate` | 起始日期 `YYYY-MM-DD`，服务端按此返回 14 天 |

设备使用 RTC 的本地日期作为起始日期。日期使用项目设定的本地时区；设备和云函数必须采用相同的日期边界约定。

### 4.3 响应处理

中转函数必须返回第 3.1 节定义的字段。06 文档中 code/message/data.schedules 的示例不作为本项目响应格式。

设备按以下顺序处理响应：

1. 检查 HTTP 状态码与响应长度（上限 4096 字节）。
2. 使用 cJSON 解析 JSON；根对象、`code`、`data.days` 类型错误时拒绝本次数据。
3. 检查 `code == 200`、条数在 1..14 之间、每条日期格式合法、字段长度不越界。
4. 完整验证通过后，才更新 NVS 中的 14 天缓存。
5. 解析响应头 `Date` 并校准 PCF8563 RTC，完成 UTC 与北京时间的换算。
6. 把当天日期和对应班次数据交给 `cal_render`，刷新墨水屏。

响应超过上限、JSON 被截断或字段校验失败时，保留上一次有效缓存。数据源违约必须暴露出来，不能靠截断或跳过抹平 —— 截断会让页面显示错误的班次。

## 5. ESP-IDF 固件接入

设备业务代码放在 app/，不修改 firmware/ 官方 Demo。网络实现按职责拆分，供主流程调用：

| 职责 | 内容 |
|---|---|
| WiFi STA | 从 NVS 读取网络配置，连接无线网络，报告连接失败 |
| AGC OAuth | 发送 Token 请求，校验响应，返回短时 access_token |
| AGC 日历客户端 | 使用 Bearer Token 和 apiKey 调用中转函数 |
| 日历缓存 | 校验完整响应后更新 14 天缓存，失败时读取旧缓存 |
| 启动流程 | 连接、取数、校时、渲染、刷新墨水屏，然后设置下一次 RTC ALARM 并进入 deep sleep |

app/main/CMakeLists.txt 目前没有声明本链路所需的网络组件。实现时应显式声明 ESP-IDF v5.4.4 的 esp_wifi、esp_event、esp_netif、nvs_flash、esp_http_client、esp-tls、mbedtls 和 json 依赖。HTTPS 使用 esp_http_client 与证书包校验；不得关闭服务器证书验证。

### 5.1 每日运行顺序

1. 读取唤醒原因、PCF8563 时间和 VL 低电压标志。
2. 从 NVS 读取 WiFi 凭据（`cal_net`）、取数凭证（`cal_agc` 的 `clientid` / `secret` / `apikey` / `groupid`）、令牌缓存，以及 `cal_sched` 班次缓存。
3. 连接 WiFi。超时后按第 6 节处理缓存和重试。
4. 判断缓存令牌能否复用；不能复用才通过 AGC OAuth 获取 access_token。
5. 若 RTC 时间可信，按本地日期计算未来 14 天范围；若 VL 标志置位，先完成可信时间初始化，再计算日期范围。
6. 调用中转函数，验证响应，写入日历缓存并依据 HTTPS Date 校准 RTC。
7. 调用 cal_render 绘制当天台历页，通过现有 EPD 驱动刷新。
8. 关闭不再使用的网络与外设，设置下一次 RTC ALARM，使用 deep sleep 省电。

日常省电流程不得调用原厂 Shutdown()；GPIO17 电池锁存按既有实现调用 rtc_gpio_hold_en(GPIO_NUM_17)。

### 5.2 首次校时与 TLS

HTTPS 证书校验需要设备系统时间处于有效范围。固件启动时执行 `SeedSystemClockFromRtc()`，把 PCF8563 的本地时间灌进系统时钟；RTC 无效或 VL 标志置位时打印「RTC 时间无效，系统时钟未设置」，本次 HTTPS 会以证书未生效失败 —— 这种情况必须先完成校时。

日常校时来源是云函数响应头的 `Date`：解析为 UTC 秒，加 8 小时得北京时间，与 RTC 比较，差异超过 5 秒才写入。不单独发起 NTP 请求。响应头缺失时不写 RTC，也不关闭证书校验。

⚠️ `esp_http_client_get_header(client, "Date", …)` 取不到这个头，实测返回空值；必须挂 `config.event_handler`，在 `HTTP_EVENT_ON_HEADER` 回调里认 `header_key == "Date"`。

### 5.3 缓存和失败处理

- 新响应只有在完整校验通过后才替换旧缓存。
- WiFi、OAuth、HTTPS、HTTP 状态或 JSON 校验失败时，间隔 1 分钟重试，最多 3 次。
- 三次失败后继续使用覆盖当天日期的有效缓存；没有可用缓存时，按 03 文档显示“获取失败”。
- 缓存不含当天日期时，不能拿相邻日期班次冒充当天数据。
- 处理完成后仍需渲染并刷新页面，再按 RTC ALARM 计划进入 deep sleep。

## 6. 设备凭据与安全

| 凭据 | 存放位置 | 使用方式 |
|---|---|---|
| WiFi SSID 与密码 | 设备 NVS | 连接 WiFi STA |
| AGC client_id 与 client_secret | 设备 NVS | 获取短时 OAuth Token |
| CUSTOM_API_KEY | 设备 NVS | 中转函数二次校验 |
| access_token | 设备 NVS `cal_agc`（`token` / `expire`） | 复用至过期前 1 小时，401 时刷新 |
| 原始班次数据源凭据 | 目标函数环境变量 | 由目标函数访问原始业务接口 |

AGC client_secret 和 CUSTOM_API_KEY 仍需存放在设备侧。项目禁止启用 Flash Encryption，NVS 不提供抗物理读取能力；因此应使用权限受限、仅能调用本中转函数的 AGC 应用身份和独立调用方密钥。原始班次接口凭据只放在目标云函数环境变量中。

不得在固件源码、构建参数、串口日志或交接文档中写入凭据。日志只记录阶段、HTTP 状态、错误类别和耗时，不记录 Token、完整请求体、apiKey 或 client_secret。

## 7. 部署与联调顺序

1. 在 AGC 建立或确认 query-schedules-range，设置 cloudgw-client 鉴权和 14 天范围限制。
2. 将真实班次数据源接入目标函数，验证其返回字段满足第 3.1 节的数据契约。
3. 建立 proxy-function，设置 apigw-client 鉴权、依赖包和环境变量。
4. 从 AGC 控制台验证目标函数拒绝端侧直接访问，中转函数只允许有效 Token、有效 apiKey 和获准 client_id 调用。
5. 使用真实 AGC 函数和真实业务数据进行电脑端 HTTPS 联调，确认 OAuth、起始日期、14 天响应、`Date` 头和权限错误。探测工具为 `tools/agc_probe.py`。
6. 实现并编译 ESP-IDF 网络组件，配置设备凭据后在 Note 4 上验证连接、Token 获取、日历解析、NVS 缓存、RTC 校时和页面刷新。
7. 完成失败缓存路径与 RTC ALARM / deep sleep 联调。烧录前按 docs/01 复核 16 MiB Flash 备份与校验结果；不得烧写 eFuse。

## 8. 验收条件

### 云函数侧

- 目标函数实际查询业务数据并返回完整的 14 天日历契约。
- 直接调用目标函数会被 cloudgw-client 拒绝。
- 无 Token、错误 Token、错误 apiKey、未授权 client_id 和非法日期范围分别被拒绝。
- 已确认 AGC 事件中的 client_id 来源，白名单校验真实生效。
- 中转函数返回的 Date 头可解析，响应中没有 Token 或密钥。

### 固件侧

- WiFi 连接失败时有明确错误记录，不会继续使用未初始化的网络状态。
- Token 获取成功后才调用中转函数；过期 Token 会重新获取。
- 只接受 `code == 200`、条数在 1..14 之间、日期格式与字段长度合法的响应。
- 字段缺省按「该天没有排班」处理，与拉取失败区分。
- 新数据完成验证后才写入 NVS；失败后原缓存仍可读取。
- RTC 校准、当天页面渲染与 EPD 刷新顺序正确。
- 无网络时使用当天缓存；缓存缺失时显示“获取失败”。
- 每日流程最后进入 deep sleep，由 RTC ALARM 唤醒；GPIO17 锁存保持有效。

所有联调使用已部署的 AGC 函数和实际业务数据。06 文档中的日期回显示例仅用于说明调用形态，不能作为功能验收结果。
