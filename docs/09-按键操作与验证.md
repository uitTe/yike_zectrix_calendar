# 按键操作与验证

## 操作

| 按键 | 操作 | 行为 |
|---|---|---|
| 正面 BOOT，GPIO0 | 深度休眠时短按 | 唤醒芯片、刷新当天页面，刷新后保留 30 秒操作时间 |
| 侧边上键，GPIO39 | 醒来期间按住至少 3 秒并松开 | 执行 esp_restart，刷新当天页面并设置下一次零点闹钟 |
| 侧边上键，GPIO39 | 醒来期间一直按住到 8 秒 | 执行 esp_restart 并进入配网模式，不必松开 |
| 正面 BOOT，GPIO0 | 配网窗口打开期间短按 | 退出配网并重启；凭据已在 NVS，重启后直接显示台历页 |
| 侧边下键，GPIO18 | 短按或长按 | 没有配置业务操作。原厂固件里它是电源键（长按 3 秒真断电），业务固件不接管 |
| 侧面 RESET | 按下 | 硬件复位 |
| BOOT 与 RESET | 按住 BOOT 再按 RESET，随后松开 BOOT | 进入 ROM 下载模式 |

BOOT 唤醒后，如果继续按住 BOOT 或上键，操作时间会延长到松开后的 30 秒。上键长按在稳定松开后执行复位，避免持续按住造成重复重启。短按上键不触发复位。

上键是两段式的：3 秒到 8 秒之间松手走重启刷新，一直按到 8 秒则不等松开就重启并进入配网模式。两段之间留 5 秒缓冲，重启刷新的原有语义不受影响。

**配网中途想退出，按一下 BOOT。** 上键那条「3 秒退出」的判定要走 `CalendarResetButton` 的去抖流程，按下与松手各有 40 ms 的采样延迟，判定的按住时长有 ±40 ms 误差——按「数到 3 秒」常常差几十毫秒落在阈值下方而不触发，再按久一点又会撞上 8 秒那条进配网的分支，重启后仍停在配网页。

BOOT 退出**不判按下时长**（2026-10-26 修正）。原来要求「按下到松开不到 500 ms」，实测按不到那么快——600 ms 就没有反应，这条通道等于不存在。配网期间 BOOT 没有其它语义，去掉阈值不会有副作用。配网模式见 `docs/12-WiFi配网与连接.md`。

无人操作时恢复 deep sleep。日常零点自动刷新仍由 PCF8563 ALARM 经 GPIO5 触发。GPIO0 与 GPIO5 同时配置为低电平 EXT1 唤醒源；入睡前等待按键稳定松开，保持 GPIO17 电池供电。班次与时段区域按取数结果绘制：取数失败时用 NVS 缓存，缓存也没有才画「获取失败」；该天没排班则留白。

**不做真关机。** 原厂长按下键 3 秒执行 `Shutdown()`，拉低 GPIO17 断掉电池轨，整机无电、RTC 与按键都唤不醒，当天不会自动刷新。业务固件不接管这个动作，省电统一由 deep sleep 承担：日常无人操作时整机停在 deep sleep，零点照样唤醒刷新，用户不必手动开机。

## 软件验证

`tools/calendar_clock_test.py` 编译并运行生产代码的日期计算与按键判定。已通过：短按、2999/3000 ms 边界、按下与松开去抖动、持续按住、启动时保持按下、单次松开只触发一次；36,524 个日期的零点计算保持通过。

业务代码位于 `app/main/`，官方 `firmware/` 组件保持只读复用。上键由独立 FreeRTOS 任务采样，能够在历法检查、页面绘制和操作等待期间响应。
